# 屏译通 UI 设计规范

> **本文件是设计源文件，不是设计说明。**
>
> 与界面相关的每一个取值——颜色、间距、圆角、字号、动效时长与缓动曲线——
> 都在 `src/pingyitong/ui/design/tokens.py` 中以代码形式定义，
> 本文件说明其来源与用法。修改界面外观应当只改令牌文件，
> 界面代码中不应出现任何硬编码的视觉常量。

---

## 一、设计规范来源与合规

### 1.1 mozilla/OpenDesign

**仓库性质**：Mozilla 的社区设计协作仓库（含 issue 模板与设计资产归档），
2019 年归档。代码部分采用 **MPL-2.0**，设计作品采用 **CC0-1.0**
（公有领域贡献）。

**其核心主张**（摘自仓库 README）：

> "Mozilla Open Design aims to bring open source principles to
> Creative Design."
>
> "NOTE: Once you've completed a project please include the source files!"

**本项目据此落实的四项工程约定**：

| 原则 | 在本项目中的落实 |
| --- | --- |
| **交付设计源文件** | 设计令牌以可读的 Python 常量定义（而非二进制设计稿），设计规范以 Markdown 交付，两者都可被非开发者直接审阅与修改 |
| **开放可复用** | 设计令牌不设额外限制，可被其他项目直接取用；引用来源在本文件与 `LICENSE` 中标明 |
| **隐私与信任优先** | 界面如实呈现"全离线、数据不出端"这一核心承诺，不设置"限时免费""立即升级"之类的诱导性文案；隐私说明常驻显示而非藏在折叠项里 |
| **无障碍作为硬约束** | 正文对比度不低于 WCAG AA（4.5:1）；关键状态不依赖颜色单独传达；所有交互均有键盘出口 |

### 1.2 emilkowalski/skills

**仓库性质**：Emil Kowalski 的设计工程规范（Sonner、Vaul 等知名组件的作者）。

**使用方式**：本项目的动效参数**逐项取自该规范**，不自行发明近似值。
规范原文明确要求：

> "Never invent `cubic-bezier(0.4, 0, 0.2, 1)` because it looks familiar."

**规范中与本项目直接相关的核心原则**：

| 原则 | 原文要点 | 本项目的落实 |
| --- | --- | --- |
| **频率闸门** | "100+ times/day → No animation. Ever." | 热键触发的一切操作不加动画；译文层刷新（15fps）不加动画 |
| **缓动曲线要强** | 内置 `ease-out` "太弱" | 使用自定义贝塞尔曲线（见 4.1） |
| **时长上限** | "UI animations should stay under 300ms" | 最长的界面动效为通知的 400ms（规范明确给通知的例外值），其余 ≤250ms |
| **绝不从 scale(0) 开始** | "Nothing in the real world appears from nothing." | 进入动效统一从 0.95~0.97 + 透明开始 |
| **只动 transform 与 opacity** | 其余属性会触发布局与重绘 | 只使用几何补间与不透明度补间 |
| **减少动态效果只减不取消** | "fewer and gentler, not zero" | 保留不透明度过渡，去掉位移与缩放 |

## 二、设计令牌总览

令牌定义于 `src/pingyitong/ui/design/tokens.py`。

### 2.1 间距（4px 基准网格）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `SPACE.xxs` | 2 | 标签与说明文字之间 |
| `SPACE.xs` | 4 | 紧邻元素的间隙 |
| `SPACE.sm` | 8 | 控件内部、图标与文字之间 |
| `SPACE.md` | 12 | 设置行内部间距 |
| `SPACE.lg` | 16 | 卡片内边距、设置行之间 |
| `SPACE.xl` | 20 | 面板内边距 |
| `SPACE.xxl` | 24 | 分页内容边距 |
| `SPACE.xxxl` | 32 | 大区块分隔 |

**规则**：所有间距必须是上表中的一个值。不出现 `13px`、`18px` 这类
"看起来差不多"的数值——它们正是让界面显得不够精致的根源。

### 2.2 圆角

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `RADIUS.sm` | 6 | 按钮、输入框、下拉框、徽标 |
| `RADIUS.md` | 8 | 卡片、面板、悬浮控制条、通知 |
| `RADIUS.lg` | 12 | 对话框、区域框选提示框 |
| `RADIUS.pill` | 999 | 胶囊形（保留） |

### 2.3 字体与字号

**字体族优先级**（`FONT_FAMILIES`）：

```
Microsoft YaHei UI → Microsoft YaHei → PingFang SC → Source Han Sans SC
→ Noto Sans CJK SC → Segoe UI → Arial
```

选择策略：**按优先级探测系统中实际可用的字体，而不是把整个候选列表交给 Qt**。
Qt 的字体回退行为在不同版本间不一致，显式探测可以确保中文字形不会回退到
点阵宋体——中文界面最忌讳这一点。

等宽字体（`MONO_FONT_FAMILIES`）用于展示路径、热键等技术信息：
`Cascadia Mono → Consolas → JetBrains Mono → Courier New`。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `FONT_SIZE.caption` | 11 | 辅助说明、隐私提示 |
| `FONT_SIZE.small` | 12 | 次要文字、按钮文案（紧凑模式） |
| `FONT_SIZE.body` | 13 | 正文（默认） |
| `FONT_SIZE.subtitle` | 15 | 卡片标题、区域框选提示 |
| `FONT_SIZE.title` | 18 | 面板标题 |
| `FONT_SIZE.display` | 22 | 关于页产品名 |

字重：`regular`(400) / `medium`(500) / `semibold`(600)。
**最多使用三个字重**——更多会让层级关系变得模糊而不是更清晰。

## 三、动效令牌

定义于 `ui/design/tokens.py`，由 `ui/design/motion.py` 消费。

### 3.1 缓动曲线

与 CSS `cubic-bezier(x1, y1, x2, y2)` 一一对应，Qt 侧通过
`QEasingCurve.addCubicBezierSegment()` 精确映射，**不是近似**。

| 令牌 | 控制点 | 用途 |
| --- | --- | --- |
| `EASING.out` | `(0.23, 1.0, 0.32, 1.0)` | 元素进入 / 退出（起步快，立刻给出响应感） |
| `EASING.in_out` | `(0.77, 0.0, 0.175, 1.0)` | 屏幕内的位移与形变（分段控件指示器） |
| `EASING.drawer` | `(0.32, 0.72, 0.0, 1.0)` | 大面积滑动面板（iOS 抽屉曲线） |

**禁止使用 `ease-in`**：它的起步慢，会延迟用户最关注的那一瞬间，
让界面显得迟钝。规范指出 `ease-in` 的 200ms 在感受上比 `ease-out` 的
200ms 更慢。

### 3.2 时长

| 令牌 | 值 | 适用元素 | 规范依据 |
| --- | --- | --- | --- |
| `DURATION.instant` | 0 | 键盘触发、高频操作 | "100+/day → No animation. Ever." |
| `DURATION.press` | 160 | 按钮按下反馈 | 规范"按钮按压 100–160ms" |
| `DURATION.tooltip` | 125 | 工具提示 | 规范"工具提示 125–200ms" |
| `DURATION.popover` | 200 | 弹出层、下拉、悬浮条 | 规范"下拉/选择器 150–250ms" |
| `DURATION.indicator` | 250 | 分段控件指示器、开关滑块 | 规范"标签页指示器 250ms" |
| `DURATION.modal` | 250 | 模态对话框 | 规范"模态 200–500ms" |
| `DURATION.toast` | 400 | 通知 | 规范给通知的专门取值（刻意略慢以显得从容） |
| `DURATION.stagger_item` | 300 | 逐项入场单项时长 | 规范"逐项入场 300ms" |
| `STAGGER_STEP_MS` | 50 | 逐项入场的间隔 | 规范"30–80ms 之间" |

### 3.3 缩放值

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `PRESS_SCALE` | 0.97 | 按下时的缩放（规范要求 0.95–0.98） |
| `ENTER_SCALE.popover` | 0.95 | 弹出层进入起始缩放 |
| `ENTER_SCALE.modal` | 0.96 | 模态进入起始缩放 |
| `ENTER_SCALE.tooltip` | 0.97 | 工具提示进入起始缩放 |
| `ENTER_SCALE.toast` | 1.0 | 通知采用位移入场，不缩放 |

**绝不使用 `scale(0)`**：现实中没有任何东西是从虚无中出现的。

### 3.4 通知参数

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `TOAST_DURATION_MS` | 4000 | 默认停留时长 |
| `TOAST_VISIBLE_MAX` | 3 | 同时可见上限 |
| `TOAST_GAP` | 14 | 条间距 |
| `TOAST_OFFSET` | 20 | 距屏幕边缘 |
| `SWIPE_DISMISS_VELOCITY` | 0.11 | 划走关闭的速度阈值（像素/毫秒） |

**速度判定**：拖拽位移超过高度的 40%，**或**速度超过 0.11 px/ms 即关闭。
只看距离会导致"轻轻一划关不掉"，必须结合速度。

### 3.5 工具提示

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `TOOLTIP_INITIAL_DELAY_MS` | 400 | 首次显示的延迟 |

**关键行为**：一旦有一条提示已经显示，相邻控件的提示**跳过延迟与动画立即出现**
（规范要求在连续浏览时 `transition-duration: 0ms`）。本项目自行实现了
`TooltipController` 而非使用 `QToolTip`，正是因为原生控件无法按
"是否刚刚显示过"动态切换延迟。

### 3.6 减少动态效果

`tokens.apply_reduced_motion(reduced)` 的行为（依据规范"更少更柔和，而非取消"）：

| 项目 | 正常 | 减少动态效果 |
| --- | --- | --- |
| 位移 / 缩放 | 正常执行 | **移除**（缩放值归 1.0） |
| 不透明度过渡 | 正常执行 | **保留**，压缩到 120ms |
| 逐项入场间隔 | 50ms | 0（同时出现） |

系统级检测：Windows 上通过
`SystemParametersInfoW(SPI_GETCLIENTAREAANIMATION)` 读取"辅助功能 →
视觉效果 → 动画效果"开关。用户也可在设置面板手动开启。

## 四、组件规范

### 4.1 按钮

**状态**：normal / hover / pressed / focus / disabled / checked

| 状态 | 表现 |
| --- | --- |
| 悬停 | 背景切换到 `surface_hover`（仅在精确指针设备上生效） |
| 按下 | 内容缩放至 0.97，160ms `EASING.out`，背景切换到 `surface_active` |
| 聚焦 | 2px `border_focus` 描边（键盘可达性的视觉反馈） |
| 禁用 | 文字 `text_muted`，背景 `surface` |

**四种变体**：

| 变体 | 用途 | 外观 |
| --- | --- | --- |
| `primary` | 主操作（开始翻译） | `accent` 实心填充 |
| `secondary` | 常规操作 | `surface_raised` + `border` 描边 |
| `ghost` | 空间受限场景（悬浮条、图标按钮） | 透明背景，悬停才显底色 |
| `danger` | 破坏性操作（清空历史） | `danger` 描边，悬停显 `danger_subtle` 底 |

**悬停的门控**：规范要求 `:hover` 动效必须有
`@media (hover: hover) and (pointer: fine)` 保护，因为触摸设备上点按会
误触发悬停态。Qt 侧的等价实现见 `Button._has_precise_pointer()`。

**按下反馈的实现说明**：CSS 的 `transform: scale()` 由渲染引擎处理、不影响布局；
Qt 若通过修改 `geometry` 模拟缩放会被布局管理器立即纠正，因此**必须**在
`paintEvent` 中通过 `QPainter.scale()` 实现。按钮暴露 `pressProgress`
属性（0.0–1.0），由 `QPropertyAnimation` 驱动，绘制时按
`1 - 0.03 * pressProgress` 缩放。

### 4.2 开关（Switch）

- 尺寸 38×22，滑块直径 = 高度 − 4；
- 滑块位置用 250ms `EASING.out` 补间，让用户确认"状态确实变了"；
- 轨道颜色**不做补间**——位置补间已足够传达状态，颜色再动会显得嘈杂；
- 聚焦时有描边。

### 4.3 分段控件（SegmentedControl）

用于"极速 1.7B / 高精度 4B"模型切换。

- 指示器是一个**整体滑动的矩形**（250ms `EASING.in_out`），
  而不是两处颜色各自变化——这样视觉上是"一个物体在移动"，
  比颜色渐变清晰得多；
- **键盘切换不做动画**：方向键属于高频操作，规范要求瞬时响应；
- 鼠标点击才播放滑动动画。

### 4.4 通知（Toast）

- 布局：右下角堆叠，最多 3 条，间距 14px，距边缘 20px；
- 类型标识：左侧 3px 色条 **+ 文字符号**（✓ / ! / ✕ / i）——
  颜色与符号并行传达，色觉障碍用户也能分辨；
- 进入：从下方 100% 高度滑入，400ms `ease`；
- 退出：**沿同一边缘滑出**（规范："对称路径才是滑动关闭之所以直观的原因"）；
- 悬停时暂停自动关闭（用户正在读，不该消失）；
- 拖拽关闭：位移 > 40% 高度 或 速度 > 0.11 px/ms；
- 超出边界时对位移施加阻尼（乘以 0.3），而不是硬性禁止；
- **同一 key 的通知替换而非叠加**：像"已切换模型"这类会连续触发的提示
  不会把屏幕占满。

### 4.5 工具提示

- 位置：默认在控件下方居中，空间不足时置于上方；
- 进入：125ms `EASING.out`，从 `scale(0.97)` + 透明开始；
- 首次延迟 400ms，**后续立即出现且不做动画**。

### 4.6 设置行（SettingRow）

统一结构：左侧标签 + 可选说明文字，右侧控件。

- 标签使用 `body` 字号、`text_primary` 颜色；
- 说明使用 `small` 字号、`text_secondary` 颜色；
- **说明文字常驻显示而非悬停才显示**——悬停提示会让用户漏读关键约束
  （例如"关闭后每帧都整屏识别，CPU 占用会显著上升"）；
- `stack=True` 时控件另起一行占满宽度，用于样式预览、区域选择等需要
  较宽空间的控件。

### 4.7 状态徽标（StatusPill）

三种色调：`info` / `success` / `warning`。

**无障碍要求**：徽标文字使用明确的词（"已就绪"、"未就绪"）而不是
仅靠颜色区分。

## 五、界面载体规范

### 5.1 原位翻译透明层

**这是产品的核心界面**，也是唯一持续刷新（最高 15fps）的界面。

| 属性 | 设置 |
| --- | --- |
| 窗口标志 | `FramelessWindowHint \| WindowStaysOnTopHint \| WindowTransparentForInput \| Tool \| WindowDoesNotAcceptFocus` |
| 属性 | `WA_TranslucentBackground`、`WA_TransparentForMouseEvents`、`WA_ShowWithoutActivating` |
| 几何 | 每块显示器一个窗口，铺满该屏逻辑几何 |

**关键决策：译文层不做动画。**

依据规范的频率闸门，"100+ 次/天"的操作不应加动画。译文层每次刷新都
重绘全部条目，若每次刷新都播放入场动画：

1. 正在阅读的文字会持续位移，**破坏原位对照**——而原位对照正是产品存在的理由；
2. 每秒十余次的动画对象创建与销毁会直接拖垮渲染性能。

因此译文层的更新是**瞬时替换**。只在"整层显示/隐藏"这类低频操作上
使用淡入淡出。

**显示模式的两种遮罩**：

| 模式 | 遮罩 | 效果 |
| --- | --- | --- |
| `cover`（完全覆盖） | 不透明白色遮罩，颜色取 `bg_color` | 原文被完全遮住，用户只看到译文 |
| `overlay`（半透明叠加） | `bg_color` 按 `bg_opacity` 叠加 | 译文压在原文上，便于对照 |

**排版策略**：译文按原文包围盒自适应。

1. 按原文行高推定初始字号（`行高 × 0.82 × 用户缩放系数`）；
2. 用 `QTextLayout` 按包围盒宽度折行；
3. 若行数或总高超出可用空间，**逐像素缩小字号重排**，直到放下或触达最小字号；
4. 仍放不下时按 `max_lines` 截断，并在末行加省略号。

使用 Qt 的 `QTextLayout` 而非自行估算换行，是为了让"预估"与"实绘"
使用同一套断行规则，避免出现预估通过但实际溢出的情况。

### 5.2 悬浮控制条

**设计目标不是"信息丰富"，而是"尽量不存在"。**

它贴在别人的界面上，存在本身就是干扰。因此：

- 高度压缩到 36px，仅保留状态点、状态文字、模型分段控件与 4 个图标按钮；
- **不做任何持续性动画**——没有呼吸灯、没有旋转指示器。
  持续动效在此处是有害的：它会持续抢走用户对真正工作内容的注意力；
- 状态用**颜色 + 文字**并行表达（"翻译中 / 已暂停"）；
- 整条可拖动，位置持久化；显示器拔掉后旧坐标可能落在屏幕外，
  此时回退到默认位置（否则控制条会"消失"且用户无法找回）；
- 显示/隐藏使用 200ms `EASING.out` 标准入场动效（偶尔触发，适用标准动效）；
  隐藏时瞬时完成（通常由热键触发，属高频操作）。

### 5.3 主设置面板

- 尺寸：最小 640×560；
- 结构：顶部状态条（状态徽标 + 模型 + 性能指标 + 主操作按钮）
  → 六个分页 → 底部常驻提示（"关闭本窗口后程序仍在后台运行"）；
- **所有设置即时生效并持久化，没有"保存/取消"按钮**：
  桌面工具的设置项大多是"调一下看看效果"的性质，要求用户先点保存
  才能看到变化是多余的摩擦；
- **破坏性操作需二次确认**，且默认焦点在"取消"上；
- 样式页带**实时预览**：改动立即反映在预览区，用户不必切回桌面查看效果。

### 5.4 系统托盘

程序唯一的常驻入口。主面板可以关闭、翻译层可以隐藏，但只要程序在运行，
托盘图标就一定在。

三态图标各自承载明确含义：

| 图标 | 状态 |
| --- | --- |
| `tray_active.png` | 翻译中（原色） |
| `tray_paused.png` | 已暂停（去色，视觉上"安静下来"） |
| `tray_idle.png` | 异常，如 OCR 组件缺失（去色 + 琥珀色调） |

菜单项用**动作命名**而非状态命名（"暂停翻译"而不是"正在翻译"），
因为菜单项是动作而不是状态显示。

### 5.5 区域框选

- 覆盖整个虚拟桌面（跨多显示器一块整体），允许从一块屏拖到另一块；
- 全屏半透明遮罩，选中区域挖空；
- 选框旁显示实时尺寸（`宽 × 高`）；
- **操作提示常驻居中显示**，而不是藏在提示框里——用户此刻正处于
  "不知道该怎么退出"的状态，任何需要额外探索的设计都会让人卡住；
- 键盘出口：`Enter` 确认、`Esc` 或右键取消；
- 过小的框选（< 24px）判定为误触，保持覆盖层打开让用户重新框选。

## 六、无障碍

| 要求 | 落实方式 |
| --- | --- |
| 正文对比度 ≥ 4.5:1 | 通过 `tokens.contrast_ratio()` 校验；`accent` 与 `accent_text` 的区分正是为此 |
| 信息不依赖颜色单独传达 | 状态点旁始终有文字；通知既有色条也有符号；徽标使用明确词汇 |
| 键盘可达 | 所有交互控件支持 Tab 聚焦并有可见聚焦环；方向键可操作分段控件；`Enter`/`Esc` 是对话框与框选的标准出口 |
| 减少动态效果 | 遵循系统设置，保留不透明度过渡、去掉位移与缩放 |
| 触摸设备不误触发悬停 | 悬停高亮仅在精确指针设备上生效 |
| 破坏性操作可防误触 | 二次确认，默认焦点在"取消"；危险按钮使用描边样式而非实心强调色 |

## 七、修改指南

### 想改主题色

只改 `tokens.py` 中 `DARK_SCHEME` / `LIGHT_SCHEME` 的 `accent` 系列。
注意：

1. `accent` 用于背景填充，`accent_text` 用于文字。若新颜色在深色背景上
   对比度不足 4.5:1，必须同时提供一个提亮版本作为 `accent_text`；
2. 改完请用 `contrast_ratio()` 校验一遍。

### 想改动效节奏

只改 `DURATION` / `EASING` / `ENTER_SCALE` / `PRESS_SCALE`。

**不要**在组件代码中写死时长——`MOTION` 是全局动效参数的唯一入口，
写死会导致"减少动态效果"模式对该处失效。

### 想加新组件

1. 在 `ui/widgets/` 下新建模块；
2. 所有颜色从 `theme.scheme` 取，所有尺寸从 `tokens` 取；
3. 若需按下反馈，暴露 `pressProgress` 属性并用
   `motion.play_press_feedback()` 驱动；
4. 若需进入/退出动效，用 `motion.enter()` / `motion.exit_widget()`；
5. 在 `ui/widgets/__init__.py` 中导出。

### 自检清单

提交界面前逐项确认：

- [ ] 没有硬编码的颜色、尺寸、时长
- [ ] 可按压元素有按下反馈（`pressProgress`）
- [ ] 进入动效不是从 `scale(0)` 开始
- [ ] 没有使用 `ease-in`
- [ ] 界面动效时长 ≤ 300ms（通知的 400ms 除外）
- [ ] 高频操作（热键、译文刷新）没有动画
- [ ] 悬停高亮有精确指针门控
- [ ] 减少动态效果模式下仍保留不透明度反馈
- [ ] 关键状态不只是用颜色表达
- [ ] 交互有键盘出口
