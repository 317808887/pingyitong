## 二、作品概要

「屏译通」是一套面向教学与学习场景的桌面端实时翻译工具，定位是"屏幕所见即所译"。程序以默认 15 帧/秒（可调 1–30 帧/秒）的画面捕获 + 画面差分算法，自动发现屏幕上发生变化的中／英等外语内容；用本地 OCR（RapidOCR 识别链）完成文字识别；交给**本地部署的讯飞星火 Spark-X2.5 大模型**完成推理翻译；最后把译文按原文包围盒坐标**原位绘制**在屏幕最上层透明窗口上，实现"沉浸式对照阅读"——用户不必逐句复制粘贴，也无需切换窗口。

系统提供**双本地模型**（Spark-X2.5-1.7B 极速 / 4B 高精度）与**三级智能调度**（手动 / 资源自适应 / 内容自适应）；推理运行时原生支持 CPU / CUDA 12.4 / Vulkan 三种后端并自动探测切换，天然具备"同一套模型在异构算力上可运行、可评估"的适配能力。全部翻译链路在本机闭环完成，历史记录仅存本机 SQLite，日志不记录屏幕内容，适合涉及隐私控制要求的真实使用环境。

关键性能实测（详见「应用成效」一节）：标准 1–2 行字幕的端到端 p95 时延 141–297 ms，通过 300 ms SLA；模型启动预热后单句推理 60–141 ms；双模型实测并集确定支持 137 种语言。

## 三、解决的教育（产业）痛点

1. **课堂视频与屏幕内容"字幕缺失"**。Coursera、YouTube、TED、开源课程、工业软件自带画面里的英文，多数没有中文硬字幕；学生在观看时需要频繁暂停、复制、跳转外接翻译软件，打断学习节奏。
2. **通用交互式翻译工具不贴合教学场景**。在线上打开屏幕、师生共用一机、不断框选/粘贴的情况下，翻译成本高、错位频繁、缺乏术语一致性；术语错译一旦发生，还会随学生笔记沉淀成错误认知。
3. **云翻译方案的合规与隐私顾虑**。涉及用户屏幕、文档、源代码的内容经云端翻译，存在个人信息与敏感内容外泄风险；在校园、科研、涉密教学场景下，"屏幕内容离开本机"通常不可接受。
4. **终端算力差异大，标准单一的部署方案覆盖不足**。不同学生、教室、机房的显卡与驱动差异巨大（既有纯集显 8GB 内存的笔记本，也有新款 GPU），一次部署若不能在 CPU、NVIDIA CUDA、兼容 Vulkan 的多类设备上都能跑起来，落地面会很窄。
5. **术语一致性缺乏工程化工具**。英语授课环境下，school subject 术语（医学、物理、化学、生物、数学、历史、软件与 AI 等）译名不一致会让同一门课前后对照出现"看不懂为什么换了叫法"的问题。

屏译通针对以上五点给出一体化方案：原位渲染解决"节奏断裂"，术语库解决"前后不一致"，纯本机链路解决"隐私顾虑"，多后端自动探测 + 硬件无感适配解决"终端算力差异"，本地大模型解决"翻译质量与响应速度的平衡"。

## 四、技术创新点

### 4.1 异构算力自适应推理底座（赛道核心创新）

- **三后端自动探测**：推理侧 `components/llm/backend.py` 在启动时自动检测可用后端，在 **CPU / CUDA 12.4 / Vulkan** 三种运行时之间自动选择，并把模型层完整卸载到检测到的 GPU，无需用户配置。
- **真实验证案例**：在 RTX 5070 Ti 上，因 CUDA 12.4 尚不支持 Blackwell 架构的 sm_120 计算能力，CUDA 后端自动失效后系统**自动切换到 Vulkan 后端继续推理**——这在新显卡"老框架天生跑不起来"的场景里体现出了异构算力自适应的真实价值。
- **外部进程推理耦合，运行时可替换**：LLM 推理通过 `llama-server` 外部子进程与本机回环 API 相连，推理运行时干净地被抽象为可插拔模块（`llama-cpp-python` 仍保留作为兼容路径）。这一抽象为后续替换为国产 NPU 专用推理运行时（例如通过离线转换工具链适配昇腾、摩尔线程等平台）保留了清晰的工程接口；具体加速卡实测数据以项目真实记录为准【待填写：昇腾/摩尔线程等国产平台接入实测数据与平台名称】。
- **本地量化权重**：模型权重采用 GGUF Q4_K_M 本地量化产物（1.7B 1.03 GB、4B 2.42 GB），天然适合跨算力平台部署。

### 4.2 双模型三级自适应调度

- **三级调度**（手动 / 资源自适应 / 内容自适应），核心调度逻辑在 `core/model_scheduler.py`：
  - 资源侧：CPU 持续 70%（3 s）以上自动切换到 1.7B；GPU 显存阈值 2048 MB；
  - 内容侧：文本长度阈值 80 字符、学术术语密度阈值 0.15 自动切换到 4B；
  - 时延阈值：端到端累计超过 3.0 s 自动降级为 1.7B 保响应速度。
- **双模型池策略**：1.7B 常驻 + 4B 按需加载，空闲 180 s 自动卸载，防止 8GB 内存机型的内存争抢；这也是"多算力平台下同时兼顾响应速度与内存足迹"的调度思路缩影。

### 4.3 原位渲染引擎（"沉浸式对照阅读")

- 译文按原文包围盒**原位**绘制在透明置顶层，鼠标穿透，不遮挡正常操作；支持完全覆盖 / 半透明叠加两种对照模式；多显示器、150%/200% 高 DPI 缩放下的物理→逻辑坐标换算有专门的回归测试（`tests/test_geometry.py`，遵循 Qt `QHighDpiScaling` 规则"原点不缩放，只缩放尺寸"）。
- **语义化排版**（自研）：按垂直重叠聚类成行、合并行内相邻块、按间距分段、修复断词、阅读顺序重排（XY-cut 分栏、行序）；阅读方向按中英对照习惯还原。
- **最小字号下限 12 px**（0.6.41 起），避免 OCR 误识别造成画面噪声；自适应换行与字号，保证可读性。

### 4.4 端侧全本地隐私闭环

- 屏幕捕获、OCR、大模型推理、原位渲染**全部在本机闭环**；
- 翻译历史仅存本机 SQLite，支持关键词检索与 TXT/CSV 导出；
- 日志不记录屏幕识别文本与翻译结果的内容，仅记录字符数等元信息（`utils/logger.py` 的 `describe_text`）；
- 用户可关闭"记录原文"，此时仅保存译文。

### 4.5 面向教学场景的辅助工程

- **7 门学科预装术语库**（生物、化学、历史、数学、医学、物理、软件与 AI），支持随安装包预装、随设置切换；命中的术语替换为占位符参与推理、再原样还原，保证术语翻译前后一致。
- **批量片段分隔符协议**（`<<<SEG>>>`）以单次推理处理多句片段，减少来回性能开销；片段数校验失败自动降级为逐条翻译，保证健壮性。
- **推理缓存**：跨会话 SQLite 持久缓存（4096 条 + TTL 1800 s），重复内容重复翻译成本趋近 0。
- **可选增强**：联网预翻译（可关闭）在确保合规条件下提供云端补全、支持 OpenAI 兼容的在线 AI 服务（DeepSeek、智谱、Kimi、通义等），断网时自动回退本地模型。

## 五、落地场景

1. **英文网课与教学视频实时对照**：Coursera、YouTube、TED、OpenCourseWare 等视频，原位叠中文字幕，具有"沉浸式对照阅读"体验。
2. **学术论文 / 外文教材 / 电子书阅读**：屏幕上出现的任何英文内容（PDF、网页阅读器、IDE 注释、API 文档）都可实时被翻译附上，无需截图断章、无需切窗粘贴。
3. **线下教室共用一台机器**：原位渲染竖屏/横屏自适应，适合投影、共享屏、师生共机学习，*不依赖师生用同一账号打开云服务*。
4. **Copy nothing 的快速屏幕翻译**：软件 UI、工业软件、金融终端实时英文画面，改动源程序或重跳转都很难；屏译通以上层叠加方式解决。
5. **离线 / 涉密环境部署**：纯本机链路 + 可选离线运行，适合机房、政务、科研教室等对网络受限或数据不出本机有硬约束的环境。
6. **无翻译负担的通用可访问性支持**：面向听力、阅读不便的学生，提供大字号、可选中复制、可回溯历史等通用的辅助能力。

## 七、推广与落地路径

- **零配置部署**：程序已随交付目录包含模型权重与推理运行时；安装即用，`--portable` 便携模式把配置、日志、历史库、模型全部留在程序目录且不落系统盘；安装版 `--self-check` 五项自检可立即确认运行时健康。
- **多算力覆盖**：CPU / CUDA 12.4 / Vulkan 三后端自动探测 + Vulkan 通用于各厂商 GPU、无需为不同显卡单独适配；同一套安装包不随 GPU 型号改变表现，显著降低维护成本。
- **标准化服务架构**：同一安装包支持 1.7B 极速 / 4B 高精度双模型动态切换、支持未来接入国产 NPU 运行时（保持 llama-server 外部进程接口位不变），便于增量式平台扩展。
- **推广路径**：本校校级试点 → 其他高校课程统一走教育数字化平台或机房统一部署 → 面向低带宽、离线教育场景的乡村/边远地区分发。
- **推广最小门槛**：Python 3.10+（已在 3.11.9 上完整验证）；4 核 CPU / 8 GB 内存 / 任意显卡；Windows 10/11 x86_64；纯本机、无需外网、无需账号。
