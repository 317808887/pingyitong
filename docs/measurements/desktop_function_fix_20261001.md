# 0.6.12 桌面功能复查（2026-10-01）

本轮按用户要求修复后自行安装、打开并测试。界面布局、控件、颜色、字体和样式不改；
仅修正与在线模式实际行为不符的说明，以及已有按钮的辅助功能名称。

## 已定位并修复的缺陷

- 长文本缓存键只使用前 2000 字符，尾部相反指令可能复用同一译文。现在使用完整文本 SHA256。
- 普通说明包含路径、URL 或命令选项时被当代码跳过。保留真实代码过滤，普通说明正常翻译。
- 目标语言门禁误拒绝用户明确配置的术语译法。仅放行本次源文实际命中、方向匹配的术语；
  周围未翻译的外语正文仍被拒绝。
- 本地模型重新检测会关闭仍被复用的在线连接池。重新检测只卸载本地引擎，退出程序才关闭 API。
- 预加载清理与本进程推理服务器启动存在竞态。清理在启动工作线程前完成，重复预加载不重复清理。
- 在线模式也需要 OCR 预热；现在单独启动后台预热，并与实时 OCR 串行使用同一后端。
- 历史搜索中的 `%`、`_` 被作为通配符，搜索、分页与导出结果不一致。现在按字面关键词匹配。
- 单条混合原文被 AI 插入 `<<<SEG>>>`，正确韩语/日语被误判成错误语言，额外请求后回退原文。
  单条请求保留所有子句，移除源文未包含的精确协议分隔符；多段批次仍严格对位。
- 对照模式曾按第一个 ` | ` 截断“保存 | 取消”，现仅按已知完整原文后缀解析。
  真实 API 还曾用 `<<<SEG>>>` 附上整段英文原文；现在生产请求不再要求重复原文，
  本地 `RenderItem.source_text` 保留，显示行为不变，同时防御解析精确的已知原文后缀。

处理耗时 447.7–933.5ms，p95 922.2ms。该口径从图像就绪到译文可渲染，
不含捕获等待和显示刷新。OCR 初始化另计 1520.1ms。
本轮与全套回归、构建同时运行，不将其当作严格控制资源负载的性能对比。
**300ms 目标未达成，不能把缓存耗时、本地单条推理耗时或空白画面耗时作为达标证据。**

脚本门禁可阻止不允许的文字脚本，但不能证明同属拉丁字母或西里尔字母的所有语言准确。
本轮没有声称 142 种语言均达到准确度和延迟要求。
