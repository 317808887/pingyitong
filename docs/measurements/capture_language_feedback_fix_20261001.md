# 0.6.11：译文反馈、混合语言与排队延迟修复

## 可复现原因

用户截图为自动识别源语言、目标韩语，并出现 7604ms 延迟及中英韩重叠文本。
现有 Windows 捕获未排除译文覆盖层，覆盖层上的输出会再次进入 OCR，形成不断变形的输入。
旧语言检查只判断占多数的脚本，韩语中夹着中文或英文仍会通过；旧缓存、预取和术语恢复也可能绕过检查。

真实历史日志的 7604ms 帧包括 OCR 1478ms、OCR 队列等待 2676ms、模型 3245ms。
60 帧中 17 帧超过 7 秒，最慢 16343ms（模型 12923ms）。
截图仅用于本机 OCR 审计，没有将用户截图文字发送到外部服务。
同一重叠截图的本地 OCR 首次 2602.8ms，重复图 66.0/71.4ms，不能用缓存样本声称新内容也这么快。
证据：`artifacts/latency_audit_20260930.json`。

## 实现

- 通过 Windows `WDA_EXCLUDEFROMCAPTURE` 排除本程序顶层窗口，译文显示保持不变。
  Qt 应用事件过滤器在显示及原生句柄变化时自动重设。
- 对每种字母脚本检查目标语言，豁免原文中确实存在的路径、URL、技术标识、已知缩写及品牌。
  单个普通英文词及大写自然语言标签也必须翻译；句末标点不被算作路径的一部分。
- 同语言跳过、内存缓存、预取、模型输出、术语还原及恢复请求共用检查。
  无法纠正的结果不写入译文覆盖层、缓存或历史；屏幕原文自然保留。
- 在线初次批次全部收齐后统一纠错，避免首个 worker 占用预算导致其他批次遗漏。
  正常帧使用一次批量纠错；超大帧按上下文预算拆分，最多四批有界并发。
  拒答恢复同样批量处理；本地模型保持串行。
- 三段队列合并待处理变化区域；空白 OCR 结果继续传递，旧内容删除或缩短时清理译文。
  不同语言代际、显示器、原点或图像尺寸不合并。
- 原位绘制扣除自身交互窗口区域，覆盖背景、文字及阴影；设置窗口的标题栏也包含在内。
  窗口关闭或移动后刷新差分基线，补译重新露出的内容。

没有改动界面布局、控件、颜色、字体或样式设计。

### 实际配置的在线 AI

使用保存的 DeepSeek Key、真实 ModelPool 与 TranslationService；没有改用户配置或输出凭据。
中→英、英→中、自动→中文、自动→韩语四项均检查目标语言及实际 API 调用增加，重复文本命中缓存。
例如中英混合源“安装完成后关闭窗口。Click the Settings button.”输出完整韩语。

14 块中英韩混合合成文档完整渲染 14 块，译文中没有未选择的自然语言，路径、URL、GPU 等标识保留。
首次 1226.1ms，重复 0.8ms，重复不增加 API 请求。
比较的是每块译文与屏幕位置的映射，避免把缓存/跳过条目装配顺序差异误报为缓存失败。

六组互不相同的双行字幕经真实 OCR + 在线翻译：

| 指标 | 实测 |
| --- | --- |
| 最小 | 413.6ms |
| p50 | 678.9ms |
| p95（6 样本） | 897.2ms |
| 最大 | 932.6ms |

口径为图像就绪至译文可渲染，包含 OCR 和模型/网络，**不含实际采集帧间隔和绘制刷新**。
每组文字 OCR 逐字核对正确，译文通过目标语言检查。此结果不等于屏幕实际端到端 p95。
在线延迟仍取决于服务响应，**没有达到 300ms，也不将较小样本量声称为稳定性能保证**。
