## 一、与现有架构的关系（零回归的边界）

现有链路（捕获 → 差分 → OCR → 翻译 → 渲染）主体一行不改。v1.1 将改动收敛为**三个接缝**，替代 v1 中"只加一次缓存查询"的模糊表述。

### 1.1 三个接缝

- **接缝 A — 翻译服务内的缓存查询（接口倒置）**
  定义协议接口 `PrefetchLookup`，由 prefetch 包实现；翻译服务在**内存缓存 miss 后**调用一次 `lookup(text, ctx)`。翻译服务只依赖该协议，**不得 import 字幕/网页模块**（依赖方向：现有核心 ← prefetch 实现）。
  - 字幕场景：`ctx` 含活跃轨 id，走 **fuzzy 通道**（活跃轨 ±N 行窗口）；
  - 网页/对照视图：走**精确键通道**；
  - 未开启、无活跃轨、异常、超时一律返回 `None`，等价现状。
- **接缝 B — 翻译队列优先级**
  现有推理入口增加优先级参数（实时=高、预翻译=低）。预翻译与实时翻译**共用同一 TranslationService、同一模型实例**（禁止另起实例导致显存翻倍）；实时任务入队后，当前句译完即让出，后台 worker 并发 = 1。
- **接缝 C — 渲染去重与行锁**
  RenderItem 增加来源标记（cache_exact / cache_fuzzy / live / screen）与字幕行锁（§6.3），保证同一文本同一时刻只有一条渲染指令、缓存直出后不闪烁回退。

### 1.2 架构图（示意）

```text
字幕导入/目录监视 → SubtitleSource（编码探测/ASS 清理/双语判定）→ ActiveTrackRegistry
                                                                      │ 注册/切换/注销
网页 URL/同源预取 → WebFetcher（robots/SSRF 防护/限速）→ 正文抽取 → 归一化分句
                                                                      │
                                          PrefetchScheduler（仅空闲出队；网页受盈亏门控）
              优先级：字幕播放位置当前行 > 字幕前向半径 > 下一章/下一页 > 全量余量
                                                                      │ 低优先级（worker=1，实时可抢占）
                                                          现有 TranslationService
                                                                      │ （同一本地模型实例）
                                                          PersistentSentenceCache（SQLite/WAL）
                                                                      ▲
现有链路（主体零改动）：捕获 → 差分 → OCR → 归一化 → 翻译服务
  翻译服务内：① 内存缓存命中？（现有）
          → ② PrefetchLookup.lookup(text, ctx)？（接缝 A，新增）
                · 字幕 ctx(活跃轨) → fuzzy：全轨首定位 / ±N 行窗口（rapidfuzz）
                · 网页/阅读器    → 精确键
          → ③ 本地模型推理（现有，高优先级）
          → 渲染（接缝 C：去重 + 字幕行锁）
```

### 1.3 接缝性能与线程约束

- 接缝 A 挂在 OCR 帧路径上，**总耗时预算 p95 ≤ 5ms（P1 已按此实现，实测 p95 随 P2 压测回填）**：精确键为 SQLite 索引读；fuzzy 仅在存在活跃轨时启用，窗口 ±N 行、rapidfuzz（C 实现），禁止 difflib；**全轨首定位在 worker 线程一次性完成，不允许出现在帧路径**。P1 已通过翻译服务 `set_prefetch_lookup` 挂接，常开语义（D1），异常等价 miss。
- SQLite：`journal_mode=WAL`、`synchronous=NORMAL`；读连接归属查询线程（线程局部连接），写操作单线程串行；建 `user_version` 迁移。
- 任何异常、超时、未开启、锁竞争 → 返回 `None`，静默跳过并计一次 `fallback(reason=lookup_error)`，不得阻塞或弹窗。

### 1.4 共享模型资源约束（R1 的闭环）

- 预翻译翻译 worker 并发固定为 1（抓取并发另计，默认 2）；
- 出队下一句的条件含：翻译队列深度 < 阈值、无实时推理在途；
- 实时任务入队后，后台在**句边界**让出（不强杀在途推理）；
- 验收必须包含"预翻译开关开/关两种状态下，屏幕实时翻译 p95 延迟对比"，劣化超过门槛即不通过（§10）。

### 3.1 network_monitor.py

```python
class NetworkMonitor(QObject):
    state_changed = pyqtSignal(object)          # GateState 输入信号
    def start(self, probe_interval_s: float = 10.0) -> None: ...
    def stop(self) -> None: ...
    def probe_now(self) -> NetProbe: ...
    def network_cost(self) -> NetworkCost: ...   # UNMETERED / METERED / UNKNOWN

# 判定规则（v1.1 修订）：
# 1) TCP 探测 223.5.5.5:443；
# 2) HTTP 层探测两个可配置的国内固定内容/204 端点（默认给出两个，评审时确定），
#    用于识别 captive portal（校园网/企业网 TCP 通但需网页认证的情况）；

#    / INetworkCostManager；调用失败回退网卡类型启发（排除蓝牙/虚拟交换机）；
```

出队条件（全部满足）：① 全局网关态允许该类任务（字幕只需 enabled；网页需 ONLINE 且未触顶配额）；② 该源健康态 OK；③ ResourceMonitor 空闲（CPU 低于阈值、无输入 N 秒）；④ 翻译队列深度低于阈值、无实时推理在途；⑤ 网页任务通过 econ_gate。

**预热工时账（估算 → P0 实测）**：2 小时电影 ≈ 7200/3 = **2400 行**。估算阶段最悲观档（5 行/秒）为 **480 秒**。P0 实测吞吐：1.7B 逐行 **10.4 行/秒**、批量 **22.7 行/秒**；4B 批量 **11.0 行/秒**。据此：2400 行全量预热 1.7B 批量约 **106 秒**（2400/22.7）、4B 批量约 **218 秒**（2400/11.0），均远低于最悲观估算；稳态需求仅 1/3 ≈ 0.33 行/秒，**逐行吞吐余量约 31 倍（10.4×3），取整称约 30 倍**。位置优先策略仍保留（导入时播放已开始的场景下，锚点优先决定片头体验）：

- 字幕预热锚点 = 当前播放行（未播放时为文件开头），先完成锚点 ±r 行，再随 `report_playback_line` 前向推进，余量 BULK 最后；
- 半径 r 的安全条件：译完 r 行耗时 < 播放 r 行耗时，即 `r/p < r·d` → **稳态条件 p > 1/d**（p=吞吐行/秒，d=每行停留秒数）；r 取"缓冲目标秒数/d"与队列预算的较小值；P0 实测 p = 10.4（逐行）/22.7（批量）行/秒，默认 60 秒缓冲（d=3 时约 20 行）批量约 1 秒即可备齐；
- 网页抓取并发默认 2；**翻译 worker 固定 1**，实时任务句边界抢占；
- 三重上限：每分钟请求数、单页字节数、日流量；触顶进 QUOTA_PAUSED；
- 关开关、注销轨、离开页面 → 取消对应任务（含在途批次的句间停止）。

> **P2 尾交付（2026-09-19）**：四级优先级（PLAYBACK_CURRENT > PLAYBACK_AHEAD > NEXT_CHAPTER > BULK_REST）与三重出队门控（网关/源健康态、ResourceMonitor 空闲、翻译队列深度且无实时推理在途）已实现；实时任务到达后句边界让出（R1）。两条测试逼出的取消/调度语义：① 整页 / 整轨取消时**同时拦截未来入队**，防止取消后又被重新塞回；② **队头任务被门控挡住时不阻塞队列**，跳过它向后找第一个满足门控的任务（R17）——否则单源进 COOLDOWN 后其队头网页任务会饿死后面的健康源与字幕任务。预热进度信号随 P2 尾余项交付。

## 四、状态机（v1.1 双层：全局网关态 + 每源健康态）

v1.0 的单一 FALLBACK 态会让一个坏网页源误伤字幕预热，v1.1 拆成两层。

### 4.1 第一层：全局网关态（只管"是否允许产生网络请求"）

| 状态 | 进入条件 | 退出条件 | 行为 |
|---|---|---|---|
| DISABLED | 开关关（默认） | 用户开启并通过首启同意弹窗 | 不抓取、不预热；缓存直出按 §12-D1 |
| OFFLINE | 开关开，但探测离线，或 wifi_only 下判定为计费网络且无法确认 | 探测恢复且满足网络限制 | 网页任务暂停；**字幕预热（本地文件）不受阻**；已缓存译文可读 |
| ONLINE | 在线且未触顶配额 | 断网 / 触顶配额 / 关开关 | 网页抓取与下一章预取按门控运行；字幕预热运行 |
| QUOTA_PAUSED | 触顶请求/流量日配额 | 次日时间窗重置（设置页可改配额后立即重评估） | 停止新网络任务；已缓存可读；字幕预热不受阻 |

### 4.2 第二层：每源健康态（source_id = 站点主机名 或 字幕轨 id）

| 状态 | 进入 | 退出 | 行为 |
|---|---|---|---|
| OK | 默认 / 抓取成功 | 连续 N=3 次失败 | 正常调度 |
| COOLDOWN | 连续 3 次失败（非 200、登录墙、robots 禁止、解码失败、超时） | 冷却 120s 后轻量探测成功；或用户手动重试成功 | 该源新任务暂停、排队任务取消；**不影响其他源与字幕轨**；缓存仍可命中 |

字幕文件解析失败（编码/格式）走单独的 `parse_failed` 事件与 UI 提示，不进网络冷却。

### 4.3 迁移日志

每次迁移写 INFO：`预翻译网关：ONLINE → QUOTA_PAUSED（日流量触顶 100MB）`；`源健康：example.com OK → COOLDOWN（连续 3 次：login_wall）`。状态与徽标文案一一对应：已关闭 / 离线·屏幕翻译中 / 预翻译中 / 配额已用尽 / 某源已回退屏幕翻译。

失效与容量策略：

1. **TTL**：查询惰性过滤 `expires_at`；每日清理过期行。
2. **版本失效**：查询带 `model_version = 当前版本`；旧版本行每日清理（模型升级后不显示旧译文）。当前版本指纹由 `version.py` 生成（R16）：模型文件名 + 程序版本 + chat template 内容哈希组成 **16 位指纹**；chat template 内容变化即换指纹，旧译文整体失效。缓存数据库文件为数据目录下 `prefetch_cache.db`。
3. **源更新失效**：网页 `etag`/`Last-Modified` 变化 → 删除该 `track_or_site` 全部句与行；字幕文件被同路径新文件替换 → 按轨 id 重建。
4. **容量**：默认上限 64MB，估算口径为 `SUM(length(source_raw)+length(translated))` 并预留索引与指标表余量（面板展示时给出实际 DB 文件大小）；超限按 `last_used_at` LRU 淘汰。
5. **指标轮转**：metrics 与索引保留 30 天，每日 prune。
6. schema 变更走 `user_version` 迁移脚本；安装升级与全新安装都要测试。

## 六、降级、重试与防闪烁

### 6.1 兜底顺序（不变，但明确各通道失败语义）

```text
缓存命中（精确 / fuzzy 校验通过） → 本地模型实时推理（现有链路） → 屏幕监视翻译（本就是最终兜底）
```

- 精确键 miss 是正常路径，不算故障；fuzzy 低置信或序列校验失败 → 直接走实时推理，**宁可不命中，不可错配**；
- 抓取超时 / 非 200 / 登录墙 / robots 禁止 / 解码失败 / 非 http(s) / 内网地址 → 丢弃任务并计失败，连续 3 次该源 COOLDOWN；
- JS 渲染页面不抓取（§9），阅读器与徽标明确提示"该页面无法抓取，已使用屏幕翻译"；
- 任何异常都不弹窗、不阻塞，用户始终有屏幕翻译覆盖。

### 6.2 重试

COOLDOWN 每 120s 自动一次轻量探测（robots/HEAD/小字节 GET），成功恢复 OK；FALLBACK 期间缓存照常命中；离线恢复走网关态迁移。

### 6.3 防闪烁（接缝 C）

同一 `(track_id, line_no)` 的译文一旦由缓存直出，在该字幕行显示时间窗内锁定该 RenderItem；后续 OCR 帧即使短暂 miss 也不得用实时译文替换，离开该行（时间窗结束或匹配行号前进）才解锁。网页对照视图按 block id 锁定，同理。

### 6.4 失败注入测试清单

断网、captive portal、计费网络、DNS 失败、302 跳内网、401/403、登录表单页、robots 全禁、2MB 截断、GBK/损坏字幕、ASS 特殊样式、双语文件、同路径字幕热替换、模型忙（持续高优先队列）、磁盘写满、DB 锁等待。

## 九、明确做不到 / 延后项（不静默跳过）

1. **播放器字幕流量拦截**：需 MITM + 自签 CA 信任或逐播放器插件，安全/合规重。延后；v1 用目录监视 + 手动导入 + 活跃轨覆盖主要价值。
2. **浏览器扩展 / 浏览器流量拦截**：超出桌面工具形态。延后；v1 用内置抓取 + 纯文本对照视图。
3. **云端翻译 API**：费用、隐私、数据出境需单独立项；缓存键 model_version 已为多引擎预留。
4. **JS 渲染页面**：Playwright/无头浏览器引入 300MB+ 依赖，与全离线安装包冲突；**QWebEngine 同理明确不引入**，阅读器为纯文本双栏。抓不到即回退，界面明示。
5. **服务端参数下发与指标上报**：本地 config + 本地面板 + 导出；后端立项后数据源可平替。
6. **播放器内实时字幕轨注入**：不修改播放器、不注入字幕；译文只在产品自有悬浮渲染层显示。

**P1 自查发现并修复的两个真 bug（已含回归测试）：**

1. **LRU 容量下限钳位位置错误**：小于 1MB 的合法配置被错误钳成 1MB，导致容量检查永不触发、LRU 淘汰失效。修正：钳位只作用于淘汰判定内部，不篡改用户配置；补"小容量配置必然触发淘汰"的回归测试。
2. **接缝查询源语言取值错误**：fuzzy/精确查询使用了用户配置的源语言，而非 OCR 段落实际检测值；当配置语言与画面语言不一致时缓存键永远不匹配。修正：接缝查询统一使用段落检测语言；补"配置语言≠画面语言仍命中"的回归测试。

**P1 尾 / P2 前半自查发现并修复的三个真 bug（已含回归测试）：**

3. **ASS 正则误把样式字段当正文**：解析 Dialogue 行时未限制逗号切分次数，样式字段中的逗号导致列错位、正文被污染。修正：按逗号 maxsplit=9 切分，Text 字段内部逗号安全；补含逗号对白的回归用例。
4. **VTT 无小时位时间轴解析崩溃**：仅 `mm:ss.mmm` 形式的 cue 时间戳解析抛异常。修正：小时位改为可选；补无小时位 VTT 用例。
5. **metrics 连接未释放**：指标 SQLite 连接未关闭，导致 Windows 临时目录清理失败。修正：连接生命周期收口（显式关闭 / 上下文管理）；补临时目录清理回归用例。
6. **set_active_track 清理了新轨而非旧轨的状态**（P2 尾自查，test_release_on_track_change 抓住）：切换活跃轨时按新轨 id 去清锚点与行锁，旧轨的锚点与锁原样残留——旧轨译文会泄漏进新轨的 fuzzy 匹配。修正：切换时先取旧轨 id 再清理；补"切换后旧轨状态清空"的回归用例。
